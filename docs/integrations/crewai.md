# CrewAI Integration Recipe

## The Problem
CrewAI relies on sequential, role-playing agents executing interconnected tasks. If Task A outputs a structurally malformed result or an unconstrained external response, and Task B receives it as context, the context window of Agent B will become instantly corrupted or overflowed.

## The Architecture
`secure-ingest` hooks directly into CrewAI's `Task` objects. By subclassing `Task` and overriding the `execute` method, we ensure that every single task output generated by an agent is cleanly validated, strictly typed, and stripped of excess bytes before the orchestration engine hands it off to the next agent in the sequence.

## The Recipe

```python
from crewai import Task
from secure_ingest import parse, ContentType, ParseError, StrictPolicy

# Define the structural boundary policy for all task outputs
task_output_policy = StrictPolicy(
    allowed_types=frozenset({ContentType.TEXT, ContentType.MARKDOWN, ContentType.JSON}),
    max_size_bytes=1024 * 50,  # Max 50 KB per task output
    max_depth=5
)

class SecureTask(Task):
    """A CrewAI Task subclass that validates the agent's output before continuing."""
    def execute(self, context=None) -> str:
        # 1. Execute the standard task logic (run the AI agent)
        raw_output = super().execute(context)
        
        # 2. Strict Parse and Validate
        try:
            result = parse(
                content=raw_output,
                content_type=ContentType.JSON if isinstance(raw_output, dict) else ContentType.TEXT,
                policy=task_output_policy,
                provenance=self.agent.name if self.agent else "unknown_agent"
            )
            
            # 3. Return the sanitized dict or text to the orchestrator
            return result.content
            
        except ParseError as e:
            # 4. If invalid, throw a ValueError describing the rejection
            raise ValueError(
                f"SYSTEM REJECTION: The agent's task output was rejected by structural validation protocols.\n"
                f"REASON: {str(e)}\n"
                f"AGENT FIX: Shorten your output or fix the schema structure."
            )

# -----------------
# Setup Crew
# -----------------
researcher = Agent(...)
writer = Agent(...)

# 5. Define tasks using SecureTask instead of the base Task
task_a = SecureTask(
    description="Fetch and summarize the latest tech news as JSON.",
    agent=researcher,
    expected_output="A strict JSON string of top headlines."
)

task_b = SecureTask(
    description="Write a blog post analyzing the news.",
    agent=writer,
    expected_output="A 5-paragraph markdown string.",
    context=[task_a] # Writer will only ever receive validated text/json
)
```

## The Escape Hatch
By subclassing the `Task` object, `secure-ingest` fits perfectly into CrewAI's automatic retry mechanisms.

When `secure-ingest` raises a `ValueError` because the agent generated 200KB of output instead of the allowed 50KB, CrewAI intercepts the underlying exception. The engine interprets this as a task failure and bounces the error message (Wait, `SYSTEM REJECTION: Max size exceeded`) directly back to the `researcher` agent's prompt, instructing the agent to self-correct its output and try again. The subsequent downstream `writer` agent is completely protected from the bloated payload.
